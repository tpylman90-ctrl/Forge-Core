# Forge object photo-text branch v1

## Goal and isolation

This branch maps text prompts and object images to a compact procedural object specification, then decodes it with deterministic Blender geometry. Its image CNN and text embedding start from fresh random initialization. It does not load, update, merge with, or replace any Forge Seed language checkpoint. Personal memory is not training input.

The first scope is six procedural classes: crate, stool, chair, mug, lamp, and hovercraft. This is a proof of the data and evaluation path, not an open-world 3D generator.

## Synthetic dataset

The Blender generator creates each object from eight normalized shape parameters, a text prompt, and four canonical renders (front, side, top, three-quarter). It varies dimensions, style, color, and material labels. Splits are object-disjoint: 48 training, 12 validation, and 12 test objects per class. The data is generated by repository code without third-party images or meshes and declared CC0-1.0. Its manifest records the Blender version and SHA-256 hashes for every file.

Prompts include class, descriptive attributes, and approximate dimensions, so the text-only path can be measured. Image inputs vary by view; text-only, single-view, four-view, and combined modes are reported separately.

## Fresh branch

The visual branch trains a small CNN and a separate prompt embedding, both randomly initialized. It predicts the object class and eight continuous shape parameters. Training randomly drops modalities to expose it to text-only, image-only, and combined examples. Each checkpoint stores the optimizer state, seed, dataset-manifest hash, training curve, and candidate hash.

This remains separate from the Forge Seed language model. A later experiment can test a narrow interface between them after both have reliable held-out tasks.

## Evaluation

The fixed test split reports class accuracy and normalized parameter MAE for text-only, one canonical view, four views, and combined input. A Blender evaluator builds predicted and target proxy geometry and measures silhouette IoU from front and three-quarter views.

These metrics measure a narrow synthetic task. They do not prove arbitrary photo understanding, hidden-side reconstruction from one image, production-quality topology, or general 3D competence. Human review and unseen real photos remain future evaluation gates.
