# Forge Qwen3 language sequence-distillation pilot v1

## Purpose

Test whether a small amount of text generated by the planned Qwen3-0.6B
teacher helps Forge Seed's own language model. Qwen is inference-only: its
parameters are never loaded into the Forge student. The student begins from
the verified scratch-origin 95,000-step Forge checkpoint and keeps Forge's
existing tokenizer and architecture.

## Matched experiment

The workflow generates 192 training and 32 held-out short responses with the
immutable Qwen repository revision `c1899de289a04d12100db370d81485cdf75e47ca`.
Prompts use non-personal, fictional topics to practice varied sentence forms.
The generated dataset and its hash, prompt split, teacher revision, decoding
settings, and Apache-2.0 model license are recorded in an artifact.

Two arms resume the same verified 95k checkpoint, AdamW optimizer state, RNG,
Forge tokenizer, TinyStories data, seed, and 8,000-update budget:

- **Uniform control:** batches come entirely from the pinned TinyStories
  training split.
- **Qwen arm:** 10% of sampled training sequences come from Qwen-generated
  language targets and 90% from the same TinyStories training split.

Each arm reports parent and candidate loss on the same 2,048-window,
256-token validation and independent TinyStories test sets. It also reports
loss on held-out Qwen examples and runs the existing mirrored forced-choice
and short-generation checks. Human grading is not automated.

## Interpretation and limits

This is a single-seed, exploratory test of text-prediction transfer. Qwen
outputs are synthetic targets, not verified facts. Improvement on the
synthetic held-out set alone is not enough to select the Qwen arm. A candidate
must beat the matched uniform control on independent language evaluation
without harming the capability checks; repeatable gains across seeds would
still be needed before claiming broader progress. Neither arm is promoted to
Android.
