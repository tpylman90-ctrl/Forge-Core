Task: Load a reusable scene, instantiate it, and add it as a child of the current node.
Answer:
var actor_scene: PackedScene = preload("res://actors/actor.tscn")
var actor: Node = actor_scene.instantiate()
add_child(actor)
Why: A PackedScene is a reusable resource. instantiate() creates a node hierarchy, and add_child() places it into the running scene tree.
Verify: Confirm the node appears under the expected parent in the Remote scene tree.

Task: Define a typed signal for a health change and emit it after updating health.
Answer:
signal health_changed(current_health: int)
var health: int = 100
func set_health(value: int) -> void:
    health = value
    health_changed.emit(health)
Why: A signal communicates an event to connected listeners without requiring the health owner to know each listener.
Verify: Connect a test listener and confirm it receives the updated value.

Task: Create an ArrayMesh surface from vertices and triangle indices.
Answer:
var arrays: Array = []
arrays.resize(Mesh.ARRAY_MAX)
arrays[Mesh.ARRAY_VERTEX] = PackedVector3Array([
    Vector3(-1, 0, 0), Vector3(1, 0, 0), Vector3(0, 1, 0)
])
arrays[Mesh.ARRAY_INDEX] = PackedInt32Array([0, 1, 2])
var mesh := ArrayMesh.new()
mesh.add_surface_from_arrays(Mesh.PRIMITIVE_TRIANGLES, arrays)
Why: ArrayMesh expects vertex data and optional indices in the correct array slots. Triangle indices refer to positions in the vertex array.
Verify: Add a MeshInstance3D with this mesh and inspect its winding and visibility.

Task: Apply an impulse once when a rigid body is launched.
Answer:
func launch(direction: Vector3, impulse_strength: float) -> void:
    apply_central_impulse(direction.normalized() * impulse_strength)
Why: An impulse represents a one-time change in momentum; applying it each physics frame would continuously add force.
Verify: Call launch once and compare the resulting motion with a per-frame force.

Task: Explain when to use _process and _physics_process.
Answer:
Use _process(delta) for frame-driven visual updates. Use _physics_process(delta) for physics-related movement and checks at the fixed physics tick.
Why: Separating visual timing from physics timing reduces frame-rate-dependent physics behavior.
Verify: Test the scene at different render frame rates and confirm physical motion remains consistent.
